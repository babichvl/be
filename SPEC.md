## Файлы проекта (GitHub: babichvl/be)

### ОСНОВНОЕ ПРИЛОЖЕНИЕ
```
index.html                     | Основная разметка, структура, все вкладки, модальные окна
app.js                         | Инициализация приложения, управление вкладками, Telegram WebApp
style.css                      | Глобальные стили, переменные, адаптивность
```

### STORE'Ы (управление данными)
```
workouts-store.js             | Загрузка тренировок из Supabase, realtime-синхронизация
clients-store.js              | CRUD операции с клиентами, связь trainer↔client
triggers-store.js             | Загрузка 12 триггеров, сохранение настроек в trigger_settings
```

### UI-КОМПОНЕНТЫ (интерфейс, вкладки)
```
clients-ui.js                 | Вкладка "Клиенты": список клиентов, добавление, модальные окна
clients.css                   | Стили для вкладки "Клиенты" и её элементов
triggers-ui.js                | "Сообщения/Триггеры": 12 карточек, редактирование, модальные окна
```

### РАСПИСАНИЕ (вкладка "Расписание")
```
calendar-scheduler.js         | Сетка часов на день (08:00-22:00, 15-мин интервалы)
calendar-scheduler.css        | Стили сетки, layout, ячейки, цвета тренировок
```

### МОДАЛЬНОЕ ОКНО ДОБАВЛЕНИЯ ТРЕНИРОВКИ
```
workout-modal.js              | Форма добавления тренировки (клиент, тип, время, проверка конфликтов)
workout-modal.css             | Стили окна, overlay, анимация показа/скрытия
```

### Кто ты и что делаем
Ты — опытный full-stack разработчик. Мы создаём GymBro — Telegram Mini App для фитнес-тренеров.
Пользователь не программист, поэтому инструкции должны быть простыми и конкретными.

4. Уточни у пользователя задачу сессии, если не указана явно

- В конце каждого ответа — список файлов для создания/обновления

Не трогать другие вкладки, если не сказано явно.

### Чего не делать

## 1. Общее описание продукта

**Название:** GymBro  
**Тип:** Telegram-бот + Mini App (WebApp)  
**Цель:** помочь фитнес-тренерам вести клиентов, а клиентам — отслеживать прогресс.

**Ключевые отличия:**
- Умные триггеры удержания клиентов
- Голосовое создание программ тренировок через ИИ
- Публичный профиль тренера + реферальная система
- Простота для пользователей без технических навыков

**Платформа:** Telegram (бот + Mini App)  
**Язык:** русский и английский (по языку Telegram)  
**Масштаб MVP:** до 100 пользователей  
**Срок MVP:** 4 месяца от старта разработки

### Правила безопасности (для разработчика)
- Никогда не вставлять реальные токены и ключи в код
- Бэкенд: только `os.environ.get("BOT_TOKEN")` и т.д.
- Фронтенд: допустим только публичный `anon key` Supabase
- В коде фронтенда не должно быть слов `service_role`, `secret`, `bot_token`

## 2. Роли

| Роль | Описание |
|------|----------|
| **Тренер** | Управляет клиентами, расписанием, программами, триггерами |
| **Клиент** | Записывается на тренировки, выполняет программы, отслеживает прогресс |
| **Лид** | Взаимодействует через публичный профиль, может отправить заявку |
| **Администратор** | Доступ к метрикам продукта |

Регистрация — только через Telegram (Telegram Login). Email/пароль не нужен.

## 7. Структура базы данных (Supabase)

Все таблицы созданы. Основные:

### Core Tables

| Таблица | Назначение | Основные поля |
|---------|-----------|---------------|
| `users` | Тренеры и клиенты | `id`, `tg_id` (уникальный), `role` (trainer/client), `name`, `phone`, `email`, `avatar_url` |
| `trainers` | Профили тренеров | `id`, `tg_id`, `bio`, `specialization`, `experience_years`, `rating`, `hourly_rate`, `phone`, `telegram_username` |
| `clients` | Клиенты тренера | `id`, `trainer_id`, `user_id`, `status` (active/inactive/paused), `joined_date`, `notes` |

### Занятия

| Таблица | Назначение | Основные поля |
|---------|-----------|---------------|
| `workouts` | Тренировки | `id`, `trainer_tg_id`, `client_id`, `date`, `time`, `type` (personal/group/online/intro/split), `duration_minutes`, `status` (scheduled/completed/cancelled), `google_event_id`, `jitsi_url` |
| `events` | События (синхронизация с Google Calendar) | `id`, `trainer_tg_id`, `workout_id`, `google_event_id`, `synced_at` |

### Программы

| Таблица | Назначение | Основные поля |
|---------|-----------|---------------|
| `programs` | Программы тренировок (шаблоны) | `id`, `trainer_id`, `name`, `description`, `duration_weeks`, `difficulty_level`, `is_template`, `created_at` |
| `program_days` | Дни программы | `id`, `program_id`, `day_number`, `focus` (strength/cardio/flexibility), `notes` |
| `exercises` | Упражнения | `id`, `program_day_id`, `exercise_name`, `sets`, `reps`, `weight`, `rest_seconds`, `order`, `notes` |

### Триггеры

| Таблица | Назначение | Основные поля |
|---------|-----------|---------------|
| `trigger_settings` | Настройки 12 триггеров | `id`, `trainer_id`, `trigger_key` (birthday, inactive_14d, ...), `is_enabled`, `bonus_type` (discount_percent/points/none), `bonus_value`, `message_text`, `created_at` |
| `trigger_logs` | Журнал срабатываний | `id`, `trainer_id`, `client_id`, `trigger_key`, `action_taken`, `triggered_at`, `message_sent` |

### Система баллов

| Таблица | Назначение | Основные поля |
|---------|-----------|---------------|
| `points` | Баллы клиентов | `id`, `client_id`, `amount`, `reason` (workout/referral/review/bonus), `created_at`, `expires_at` |

### Реферальная система

| Таблица | Назначение | Основные поля |
|---------|-----------|---------------|
| `referrals` | Реферальные ссылки | `id`, `referrer_tg_id`, `referee_tg_id`, `referral_code`, `status` (pending/active/completed), `created_at` |

### Служебные таблицы

| Таблица | Назначение | Основные поля |
|---------|-----------|---------------|
| `calendar_delete_queue` | Очередь удаления из Google Calendar | `id`, `trainer_tg_id`, `google_event_id`, `created_at`, `status` (pending/processed) |

## 9. Краткое описание каждого файла

### Основное приложение

**index.html**
- Разметка всех 4 вкладок, шапка, нижняя навигация
- Подключение всех скриптов (.js) в правильном порядке
- Div-контейнеры для каждой вкладки
- Модальные окна (добавление клиента, редактирование триггера, добавление тренировки)

**app.js**
- Инициализация приложения при загрузке
- Управление переключением между вкладками
- Инициализация всех Store'ов (WorkoutsStore, ClientsStore, TriggersStore)
- Инициализация всех UI (ClientsUI, TriggersUI)
- Обработка Telegram WebApp API (`window.Telegram.WebApp`)
- Получение `tg_id` пользователя для загрузки его данных

**style.css**
- Глобальные стили (переменные цветов, типографика, layout)
- Стили для хедера, табов, FAB-кнопки
- Адаптивность под мобильные устройства
- Тёмная тема (если нужна)

### Store'ы (слой управления данными)

**workouts-store.js**
- Загрузка тренировок из `workouts` таблицы Supabase
- Realtime-подписка на изменения (INSERT, UPDATE, DELETE)
- Методы: `init()`, `getAll()`, `subscribe()`, `addWorkout()`, `updateWorkout()`, `deleteWorkout()`
- Синхронизирует данные между Главной и Расписанием в реальном времени

**clients-store.js**
- Загрузка клиентов из таблицы `clients`
- CRUD операции (Create, Read, Update, Delete)
- Методы: `init()`, `getAll()`, `getByTrainerId()`, `addClient()`, `updateClient()`, `deleteClient()`
- Связь: `trainer_id` ↔ `client_id`

**triggers-store.js**
- Загрузка 12 триггеров из таблицы `trigger_settings`
- Каждый триггер имеет: `is_enabled`, `bonus_type`, `bonus_value`, `message_text`
- Методы: `init()`, `getAll()`, `getByKey()`, `update()`, `subscribe()`
- Realtime-обновление при изменении триггера

### UI-компоненты (интерфейс)

**clients-ui.js**
- Рендеринг вкладки "Клиенты"
- Две под-вкладки: "Клиенты" и "Сообщения/Триггеры"
- Список клиентов с кнопкой "+ Добавить"
- Модальное окно добавления клиента (имя, телефон, email)
- Сохранение в ClientsStore → Supabase

**triggers-ui.js**
- Рендеринг вкладки "Сообщения/Триггеры"
- 12 карточек триггеров (иконка, название, описание, тумблер)
- Клик на карточку → модальное окно редактирования
- В модальном окне: тип бонуса, значение, текст сообщения
- Сохранение в TriggersStore → `trigger_settings` в Supabase
- Обработчики событий переприкрепляются при открытии модального окна (fix для бага с потерей обработчиков)

**calendar-scheduler.js**
- Визуализация сетки часов (08:00–22:00, 15-минутные интервалы)
- Отображение тренировок в слотах
- Клик на слот → открыть модальное окно добавления
- Методы: `init()`, `updateWorkouts()`, `render()`

**calendar-scheduler.css**
- Стили сетки (grid layout, ячейки)
- Стили для тренировок (цвета по типам)
- Переходы и анимации

**workout-modal.js**
- Модальное окно для добавления/редактирования тренировки
- Форма с полями: клиент (select), тип (select), время, длительность
- Кнопки: "Отмена", "Сохранить"
- Валидация: проверка конфликтов (две тренировки на одно время)
- Методы: `init()`, `open()`, `close()`, `save()`
- При сохранении → WorkoutsStore → Supabase + Google Calendar

**workout-modal.css**
- Стили для overlay (затемнение фона)
- Стили для окна (позиционирование, размеры)
- Анимация показа/скрытия

### Интеграции

**google_sync.js**
- При добавлении тренировки синхронизирует с Google Calendar
- Отправляет запрос на бэкенд для создания события
- Получает ссылку на видеотренировку (для онлайн-тренировок через Jitsi)

**google_calendar_delete.js**
- При удалении тренировки добавляет запись в очередь `calendar_delete_queue`
- Бэкенд периодически проверяет очередь и удаляет события из Google Calendar

### Бэкенд (main.py)

Основная логика:
- Webhook для обработки сообщений от Telegram
- Команды: `/start`, `/webapp` (открыть Mini App)
- Отправка сообщений клиентам при срабатывании триггеров
- Синхронизация с Supabase
- Интеграция с Google Calendar API
- Обработка очереди `calendar_delete_queue`
